## 5. Suspected defect withdrawn (driver artifact)

After entering the 6-digit code, new accounts landed on Home ("Registre un contribuyente para ver su
inicio.") instead of the onboarding, with the dashboard ON and OFF. Instrumented profile builds showed the
launcher **did** push the onboarding, and the onboarding was popped about 350 ms later by a route pop the
app never made: the QA driver sent `KEYCODE_BACK` (to hide the keyboard) right after typing the code, and
the code field submits by itself. Without that key event the onboarding opens every time (`24`). No app
change was made; a fix written before the cause was found was discarded. The widget test written while
investigating stays, as coverage for M6 (Home's body moved behind `module_dashboard`):
`mobile/test/features/taxpayers/onboarding_after_sign_up_test.dart` (new account → onboarding with the
dashboard ON and OFF, also after another account signed out).

## 6. Screen reader

TalkBack was enabled on the emulator, but adb-injected touches do not go through explore-by-touch, so
focus could not be moved onto the chart from the driver (`26a`, `27`). The accessibility node tree that
TalkBack reads was checked instead (uiautomator): the chart is one container labelled with its summary
("Impuestos estimados, últimos 10 meses. Octubre: 4,181 pesos con 66 centavos, incompleto. Mes más alto:
enero, 5,583 pesos con 65 centavos."; the income view: totals for the period), and each bar has its own
label with every value and the status. The widget suite pins the same (`dashboard_home_test.dart`, "taxes by
default, with a screen-reader summary"). A manual TalkBack pass on a real device is still owed.

## 8. Environment notes (kept apart from app bugs)

- Gboard's clipboard and settings screens opened twice from injected key events (`KEYCODE_ESCAPE`, a tap on
  the keyboard strip); recovered by returning to the app.
- To restart its own API on another port, this run used `pkill -f "go-build.*/api$"`, a pattern that would
  also stop another agent's `go run ./cmd/api`. No other API was listening afterwards; whether one was
  running before is unknown. Future runs should kill by PID.
