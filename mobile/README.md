# Control Contable — mobile (Flutter)

Flutter client for Control Contable. Stack and pins: [ADR-0001](../docs/adr/0001-stack.md)
(mobile section). Toolchain: **Flutter 3.47.7 / Dart 3.13.5**.

## Prerequisites

- Flutter 3.47.7 (`flutter --version`).
- Android: Android SDK (Android Studio). iOS: full Xcode + CocoaPods (owner item OB6).
- The API on port 3000, or the Prism mock on port 3001 (`make mock`), which works before
  the backend does.

## Everyday commands (from the repo root)

| Command | What it does |
|---|---|
| `make mobile-check` | `dart format --set-exit-if-changed .`, `flutter analyze` (0 issues), `flutter test` |
| `make mobile-client` | Regenerates the API client from `docs/api/openapi.yaml` ([ADR-0003](../docs/adr/0003-dart-client-generation.md)) |
| `make mobile-client-check` | Drift check: fails if the committed client differs from the contract |
| `make mobile-test-mock` | Integration tests against the Prism mock (start `make mock` first) |
| `make mobile-run` | Runs the dev flavor against `http://localhost:3000` |
| `make mobile-run-mock` | Runs the dev flavor against the Prism mock, `http://localhost:3001` |
| `make mobile-run FLAVOR=staging API_BASE_URL=https://…` | Runs another flavor |
| `make mobile-build-apk FLAVOR=prod API_BASE_URL=https://…` | Obfuscated release APK |
| `make mobile-build-aab FLAVOR=prod API_BASE_URL=https://…` | Obfuscated release app bundle (Play upload) |
| `make mobile-cover` | Tests with coverage; fails below 80% on non-generated `lib/` code (`tool/coverage_gate.dart`) |
| `make mobile-artifact-check FLAVOR=prod` | Fails if the release APK/AAB ships symbols, debug info, `.map` files or `sourceMappingURL` (`tools/mobile/check-release-artifact.sh`; macOS: `READELF=<ndk>/llvm-readelf`) |

CI (`.github/workflows/mobile.yml`) runs format, analyze, `mobile-cover`, then the prod APK +
AAB build and `mobile-artifact-check`. The split debug info (`build/symbols/prod`) never ships in
the app and is not uploaded as a CI artifact either: the repository is public, so artifacts are
public too (P0-30). Release symbols go to crash reporting in REL-04. An AAB's
`BUNDLE-METADATA/` (native symbol tables, R8 `proguard.map`) is Play-only and allowlisted:
`flutter build appbundle` refuses to finish without it.

An Android emulator reaches the host as `10.0.2.2`: add `API_BASE_URL=http://10.0.2.2:3000`.

HTTP (`AppConfigError`), so no environment host is baked into the source.

Android product flavors live in `android/app/build.gradle.kts`. **iOS schemes are pending**:
they need a full Xcode (OB6). Until then, run iOS with `-t lib/main_<flavor>.dart` and no

## Layout

```
lib/
  main_<flavor>.dart     entrypoints → app/bootstrap.dart
  app/                   root widget (MaterialApp.router), bootstrap
  core/
    config/              AppFlavor, AppConfig, appConfigProvider (overridden at boot)
    flags/               AppModule, flagsProvider, ref.useFlag(), FlagGate
    forms/               AppForm, AppTextField, AppMoneyField, AppDateField (house form rules)

    router/              appRouterProvider (go_router), AppRoutes, FeatureModule, NotFoundScreen,
                         BootSplashScreen
    theme/               design tokens (ThemeExtension) and the Material mapping
  features/<module>/     one folder per module slice: <module>_routes.dart, presentation/,
                         application/, data/ — a disabled module's routes are unreachable
  api/generated/         Dart client generated from the contract: never edit by hand
  l10n/                  ARB files (es template, es_MX) + generated AppLocalizations
```

## API client

`lib/api/generated/` is generated by `make mobile-client` (normalizer → swagger_parser →
build_runner → kind guard; [ADR-0003](../docs/adr/0003-dart-client-generation.md)) and
committed. Change the contract, regenerate, commit both. Features read typed clients from
`ref.watch(apiClientProvider)` (e.g. `.platform.listEnabledFlags()`).

`dioProvider` never follows redirects (a 3xx is an error), and on HTTPS flavors
`HttpsOnlyInterceptor` refuses any `http://` request: Dart sockets ignore Android NSC and
iOS ATS, so the app enforces HTTPS itself.

## Feature flags

`GET /v1/flags` feeds `flagsProvider`, the one source of flags. Widgets read it only through
`ref.useFlag(AppModule.x)` or `FlagGate(module: AppModule.x, child: …)`. A module slice
registers its routes as a `FeatureModule` in `featureModulesProvider`. The router is built
once; a location owned by a disabled module redirects to "not found", re-checked on every
flag change, so a refresh never resets the user's navigation.

- Fail-closed: loading, a failed first fetch or a key this build does not know ⇒ OFF.
- A location inside a module opened before the first answer (deep link, notification,
  post-login redirect) waits on `/cargando`, keeps the requested location and returns to it
  once flags arrive. After `flagsBootTimeout` (8 s) without an answer it fails closed to
  "not found".
- Cached in memory; refreshed when the app resumes. A failed refresh keeps the last answer.
- UX only: the backend answering `404` for a disabled module is the security boundary.

## Forms

Every record form is built from `core/forms/`, which encodes
`~/.claude/rules/ui-forms-and-modals.md` once so screens cannot drift:

- `AppFormController` owns the fields (`textField`, `moneyField`, `dateField`) and the
  policy: required-but-empty errors on submit only; format errors on blur once the field has
  a value; after an error shows, every change re-checks it. Valid money and dates are
  rewritten in canonical form on blur. Money is read as integer centavos
  (`1,234.50` / `1234.5` / `$ 1,234.50`); dates as es-MX day/month/year in any common form,
  or ISO (never month-first).
- The server is the authority: `onSave` reports a rejected field with
  `AppFormController.showServerErrors`, which shows it inline and in the summary.
- `AppForm`: one column, `FormErrorSummary` on top (takes focus and is announced to screen
  readers on every failed submit; each item focuses its field), a sticky `FormFooter`: *Guardar* (never disabled; busy while saving,
  repeat taps ignored), optional *Guardar y crear otro* (keeps `keepForNext` fields, clears
  the rest, refocuses), *Cancelar* as text. Ctrl/Cmd+Enter submits from any field.
- `AppTextField`: label above the field, the fewer kind (optional by default) marked in text,
  `keyboardType` / `textInputAction` / `autofillHints` required. A single-line field with a
  done/go/send action submits on Enter; `next` moves on; multi-line never submits.
- `AppPasswordField`: hidden text, a labeled show/hide toggle, no suggestions; its field is
  `verbatim` (never trimmed nor rewritten). `AppCheckboxField` (`checkboxField`): the whole
  row toggles; a required box left unchecked is listed in the error summary like any field.
- Leaving a field never re-checks a shown error (changes do), so a server verdict stays
  until the value changes. `matchServerFieldErrors` maps `ErrorResponse.details` onto fields
  by dotted path (`accepted_documents.1.kind` → `accepted_documents`); the rest goes to a
  `FormNotice` (form-level message, announced).
- `guardApi` (`core/network/api_failure.dart`) turns a generated-client failure into a sealed
  `ApiFailure` (validation details, 401, `invalid_password` by its code, 404, 429 with
  `Retry-After`, unreachable, unexpected);
  screens own their es-MX copy and never show the server's English `message`.

## Auth (`module_auth`, M1)

`features/auth/` registers `/cuenta/registro` and `/cuenta/verificar` as a `FeatureModule`
(composed in `app/feature_modules.dart`); home shows *Crear cuenta* only while the flag is on.

- Register: name (optional), email, password, and the two consents. The legal documents are
  fetched (`legalDocumentsProvider`, no automatic retry; a *Reintentar* button instead); the
  links open the current version in the in-app browser view (`urlOpenerProvider`, web
  schemes only). `register` sends **only the email and the consents** (exactly the versions
  shown); a stale version unchecks both consents and reloads the documents. The password and
  name wait for the code step (D8) in a `SignUpDraft` (`pendingSignUpProvider`): memory only,
  never persisted nor in a route (process death drops it). The password survives a trip to
  the mail app; it is forgotten after 15 minutes without activity on the code step
  (`signUpIdleTimeout`, on `clockProvider`), and the whole draft on success or on going back
  to the form. The sign-up form clears its own password field once the draft holds it, so the
  draft is the only copy (going back asks for the password again).
- Verify: the 6-digit code (`AutofillHints.oneTimeCode`, digits only) is sent with the
  draft's password and name, and submits itself when complete (unless the password must be
  typed). A `401` is one generic code message; a `400` lands on its field: `password`
  (policy, length) reveals the password field with the error, `code` stays on the code. A
  forgotten password (idle timeout) shows the password field again. *Enviar otro código* appears after
  the 60 s cooldown, or after `Retry-After` when longer; the countdown runs on a clock
  deadline, so time in the background counts.
- The new session starts like a login's (`sessionProvider`; see "Session tokens" below).

## Taxpayer onboarding (`module_taxpayers`, M2-08/M2-09)

`features/taxpayers/` registers `/contribuyentes/nuevo` as a `FeatureModule`; home shows
*Registrar contribuyente* only while the flag is on (`FlagGate`). The server's `404` is the
boundary.

- `OnboardingFlow` (`application/`) holds the draft and the step; screens only render it.
  Steps, one screen each (≤ 6 fields): 1 · persona física / moral (two large cards, nothing
  asked before, OD-3) → 2 · display name + RFC → 3 · regimes → 4 · options, one page per
  chosen regime that has `option_defs`. Back (app bar or system) goes one step and keeps
  every value; changing the person type drops the regimes of the other catalog.
- RFC: typed with spaces, dashes or lower case, upper-cased on blur; length by person type,
  shape, real date and the generic RFCs are checked on blur (`domain/rfc.dart` mirrors the
  server, which decides). The check digit is never checked client-side (D-RFC).
- Regimes (`GET /v1/regimes?person_type=`) are grouped by support level (cálculo completo /
  parcial / solo explicación), each explained, under the mandatory legend
  (`core/widgets/estimate_legend.dart`). Física is multi-select, moral single-select. An
  incompatible pair (`incompatible_with`) shows its reason inline at once and blocks the step.
- Options render from `option_defs`: boolean → switch, enum → radio group, multi_enum →
  checkboxes, rate → es-MX decimal field kept as a string (`domain/decimal_rate.dart`, bounds
  compared exactly, never a float). Catalog defaults are prefilled.
- One `POST /v1/taxpayers` with a client `id` (stable across retries) creates everything.
  Server verdicts send the user to the step that owns them: RFC errors and
  `409 rfc_already_registered` to step 2, `regimes.N.options.<key>` to that regime's page,
  `422 invalid_regime_combination` to step 3; `402` shows the read-only message (no form).
- Warnings are non-blocking: `rfc_check_digit_mismatch` shows "Revisa que tu RFC esté bien
  escrito" with the RFC editable (*Continuar* as typed confirms; a change is sent with
  `PATCH rfc` first); `regime_combination_needs_cpa_review` shows the server's reason.
- With `module_tax_engine` on, an optional step 5 offers each regime's `required_inputs` for
  the current fiscal year (America/Mexico_City), written with `PUT …/tax-inputs`; *Omitir*
  skips it.
- Not here yet: the active taxpayer and the switcher (M2-10).

## Session tokens (M1-12)

- `core/session/session.dart` (`Session`): the access token lives **in memory only**; the
  rotating refresh token lives in `RefreshTokenStore` (`core/session/refresh_token_store.dart`,
  the only file that imports `flutter_secure_storage`; iOS item `first_unlock_this_device`,
  never synced). Every rotation stores the newly returned refresh token before any retry.
- A failing secure store never logs the user out silently, and its error (which may echo the
  token) is never surfaced. Each write and delete is tried 3 times. A rotated token that could not
  be saved stays in memory, the session stays signed in, and the next rotation sends it. It never
  sends the spent token still on disk, which the server would treat as reuse. A delete that keeps
  failing at sign-out wipes the whole store. If even that fails, `Session.tokenLeftOnDevice`
  turns on and the login and goodbye screens say so.
- `core/network/auth_interceptor.dart`: the bearer goes only to the configured API origin (scheme,
  host and port of `API_BASE_URL`). An absolute URL to anywhere else never sees it. On a 401, one
  **single-flight** refresh is shared by every concurrent caller, then one retry. It never
  refreshes for `/v1/auth/*`. Only a 401 (always the bearer, contract 0.3.0) refreshes: a wrong
  re-entered password on `DELETE /v1/me` is a `403 invalid_password` and passes through. A refused refresh (401/400) ends the session
  and the router shows login; an unreachable one keeps it. The rotation runs on `bareDioProvider`
  (no interceptor), so it cannot recurse.
- *Mi cuenta* (`/cuenta/perfil`, entry on the home app bar while `module_auth` is on): the name
  is editable (`PATCH /v1/me`), the email is read-only, and the legal documents link to their
  current versions. *Eliminar mi cuenta* opens the one confirmation dialog in the app, because
  the action is irreversible. The dialog explains what is lost, that the free trial does not
  restart and that a store subscription is cancelled in the store. It asks for the current
  password and has a destructive primary that is never disabled. A `403 invalid_password` lands
  on the password field (cleared, focused, announced); a `429` counts its `Retry-After` down, and
  a tap during the wait sends nothing. On success it ends the session and the app shows `/cuenta/adios`.
- Router guards (`core/router/app_router.dart`): while `module_auth` is on, a signed-out user
  goes to `/cuenta/entrar` (keeping `desde`), a signed-in user leaves the guest screens
  (login, sign-up, code). Login and a verified sign-up (`201 AuthSession`) both start the session.
- Login (`/cuenta/entrar`): bad credentials read as one generic message. A `429` counts its
  `Retry-After` down (`RetryWait`, shared with the delete dialog), and a tap during the wait
  sends nothing, so it never spends the network's login budget.
- Logout (`features/auth/application/sign_out.dart`) calls the API, then wipes locally even if
  the call fails.
- The session (refresh) token is stored **only** through `flutter_secure_storage` (ADR-0001:
  Keystore on Android, Keychain on iOS). Never through the `shared_preferences` plugin: it
  writes plain XML that a backup, `adb` on a debuggable build or a rooted phone can read.
  `test/platform/token_storage_test.dart` fails if a file using `shared_preferences` handles
  a token.
- On Android, `flutter_secure_storage` keeps the ciphertext in a shared-preferences file and
  its key in the Keystore. The manifest turns Auto Backup off and the backup rules exclude the
  whole `sharedpref` domain from cloud backup and device-to-device transfer (Android 12+) and
  from full backups (Android 11 and lower), so the token never leaves the device and a restore
  never brings back a store whose key stayed behind (`test/platform/android_backup_test.dart`).
  A secret stored anywhere outside `sharedpref` needs its own exclusion.

## Design tokens

Widgets never hard-code a color, radius or face; they read `context.tokens` (`AppTokens`, a
`ThemeExtension`) or the Material theme built from it in `core/theme/app_theme.dart`.

- `core/theme/directions/confianza_sobria.dart`: direction **A · Confianza sobria**
  ([DIRECTIONS.md](../docs/design/DIRECTIONS.md)), light and dark.
- `designDirectionProvider` picks the active direction. To change the look, add
  `directions/<name>.dart` and return it there. No widget changes.
- `test/core/theme/theme_tokens_test.dart` asserts every documented contrast pair passes AA,
  so a new direction cannot ship a failing pair.
- Fonts (Public Sans, Source Serif 4; SIL OFL 1.1, latin subset) are bundled in
  `assets/fonts/`: no runtime font fetching.

## Localization

es-MX is the only locale. Copy lives in `lib/l10n/app_es.arb` (template); `app_es_MX.arb`
holds only Mexican overrides. `flutter gen-l10n` regenerates `app_localizations*.dart`
(also run by `flutter pub get` / `flutter test`); commit the result.

## Release hardening

- Dart code: `--obfuscate --split-debug-info=build/symbols/<flavor>`. Symbols stay on the
  build machine and are never bundled (`*.symbols` is git-ignored).
- Android: R8 minify + resource shrinking on release.
- `avoid_print` is an error: production code does not print.
- The CI artifact gate (no symbols or maps inside the APK/IPA) is P0-25.
